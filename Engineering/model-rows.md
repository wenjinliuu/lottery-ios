# 模型按行读号码

2026-11 TestFlight 实测之后改的。上一版的数字模型只当「复核员」，识别率的上限仍然是 Apple Vision；
这一版模型把整行号码读一遍，和 Vision 逐个号码互相校对。

## 为什么上一版没有质的提升

| 上一版 | 结果 |
|---|---|
| 只看一位数的格子（排列3/5、3D、七星彩前六位） | 大乐透、双色球完全没用上模型 |
| 只会把格子改成问号，Vision 没读出来的不管 | 七星彩一张票 16 个问号，模型其实都认得 |
| 把握门槛 0.9，而旧模型的把握很少超过 0.95 | 一半的格子模型「不发言」 |

模型本身没有问题：三张没见过的实测照片上 329 个数字认对 327 个，错的两个是切字切错了。

## 现在的流程

1. `NumberZone`：用上下两行文字夹出号码区（体彩：「合计N元」那一行到第一句整话；福彩：哈希行到「开奖期」），拉成 1000 像素宽。
2. `GlyphRows`：局部阈值 → 切行 → 切字 → 留下长得像数字的段 → `DigitClassifier` 逐段认。
3. `GlyphRows.readLine`：一行里找**唯一**一串个数正好的数字。多一位少一位都作废。
4. `ModelFusion`：和 Vision 的结果按行配对，逐个号码合：一致采纳、不一致标问号、Vision 的问号由模型补（补完整注要合规）。

不管复式、胆拖（版式没在真票上量过）。

## 量出来的数

模型：两层卷积加两层全连接，约六万个参数。训练集是合成数字 + 第一、二批真票上抠的 821 个字；
测试集是第三批（实测用的三张照片）和网上别人分享的票，共 391 个字，一个都没参与训练。

| | 结果 |
|---|---|
| 测试集认错 | 0 / 391 |
| 把握 ≥ 0.9 的覆盖 | 388 / 391，其中认错 0 |
| 第三批按行读（不看标注） | 33 / 33 行读成，359 个数字全对 |

`ModelFusion` 在本机用 44 张真票的号码区跑过（脚本在 `lottery-ocr` 仓库，真票不进这个仓库）：

| Vision 的状态（模拟） | 体彩票（大乐透单式/套餐、排列5、七星彩） |
|---|---|
| 随机丢三成号码 | 135 个问号全部补上，错号 0 |
| 一个号都没读出来 | 501 个问号全部补上，错号 0 |
| 套餐票的「前区」整行丢了 | 5 张全部补回，错号 0 |

注意第一、二批的字参与了训练，这张表里只有第三批（6 张票）是完全没见过的。
福彩的单式票能读成的行少一些（双色球 9 行读成 6–8 行、快乐8 10 行读成 6 行），读不成的行保持 Vision 的结果。

**没有量过的**：手机上 Vision 给的文字框和这里用的开源识别不完全一样，号码区夹得准不准要看真机。
调试图的说明里有一句「模型读行：N 行号码读成 M 行…」，M 比 N 小就是这一步没到位。
